## 0. Три предмета, которые нельзя смешивать

| Предмет | Единица | Природа | Пример |
|---|---|---|---|
| **Квота организации** | доля 0..1 + срок сброса | точка во времени | «неделя занята 88%, сброс 12.11» |
| **Кошелёк** | деньги (USD) | точка во времени | «баланс $1.50» |
| **Расход** | деньги (USD) | накопление за период | «израсходовано $0.0165 с 08:38» |
| **Лимит сессии** | токены | точка во времени, на сессию | «контекст 353k из 1 048k, кэш прочитан 99.8%» |

Кошелёк и расход — оба деньги, но это **разные предметы**: остаток и накопление. Складывать долю окна с деньгами нельзя; хранить остаток и расход в одном поле — значит гарантированно однажды их перепутать.

## 0a. Карта источников: что приходит САМИМ, а что надо ЗАПРАШИВАТЬ

Ответ на вопрос фаундера 07.11: «что-то они дают сразу, а что-то надо запрашивать отдельно».
Один и тот же провайдер почти всегда раскалывается на ДВА входа: **инференс** (модель) и
**контрольная плоскость** (квота/кошелёк), и это разные ключи.

| Провайдер | Модель / протокол | Что приходит В ОТВЕТЕ | Что нужно ЗАПРАШИВАТЬ отдельно | Чем (ключ) | Оракул |
|---|---|---|---|---|---|
| **Anthropic** | Claude, `/v1/messages` (нативный) | `usage` (вход/выход, cache read/write), квота в заголовках `anthropic-ratelimit-*` | — (без отдельного опроса) | OAuth сессии подписки | **заморожен** 05.11: OAuth отключён вендором |
| **OpenCode Go** | `deepseek-v4.1-flash-go` и др., OpenAI-диапазон | `usage.opencode.list_cost` (цена), `allowance` (остаток подписки) | **окна квоты** 5ч/сутки/неделя/месяц | console-сессия (отдельный вход) | сборщик `opencode-go-quota.ts` |
| **OpenDesign** | `deepseek-v4.1-flash-od`, `-eco-od`, OpenAI | `usage` БЕЗ ЦЕНЫ (только токены и кэш) | **квота окон и кошелёк** | **Control Key** (`amr-api`), отдельный от модельного `sk-amr-…` | сборщик `open-design-quota.ts` |
| **Alibaba / Bailian** | `bailian-cli/*` | зависит от модели | квота/каталог — из console-входа | console login | сборщик `alibaba-quota.ts` |
| **Z.AI / OpenRouter и др.** | собственные | у каждого свой протокол | квота — если вообще отдаётся | свой ключ | пока **не подключены**; место в этой же таблице и в реестре |

🔴 Три следствия, из которых и растёт вся архитектура:
1. **Инференс-ключ и ключ квоты — разные.** У OpenDesign модельный `sk-amr-…` НЕ пускает в контрольную плоскость (401) — квоту видит только Control Key. Значит «есть ключ» ≠ «видим остаток».
2. **Цена приходит не от всех.** Go объявляет `list_cost`, OpenDesign не объявляет ничего → его долларовый расход сегодня НЕ измеряется (см. §2.3).
3. **Опрос и ответ живут с разной частотой.** Окна — раз в 5 минут; цена — на каждом ответе. Смешивать их в один «свежий» снимок нельзя: у каждого предмета свой возраст.

## 1. Поток целиком (одна картинка)

Отрисованная схема (обновляемая): https://dia.muid.io/d/5ecfmnsbda — «источники → концентратор → потребители».


```
                    ┌── поставщик (Control API / ответы) ──┐
                    │                                     │
   квота ───────────┤ сборщик провайдера                   │
   (одна программа  │ пишет quota-status-<provider>.json   │
    на провайдера)  │ ОДИН писатель на файл                │
                    │                                     │
   расход ──────────┤ LiteLLM (x-litellm-response-cost)     │
                    │ + сборщик dsh                        │
                    │ пишет spend-<provider>-<экз>.json    │
                    │ ОДИН писатель на файл                │
                    │                                     │
                    │ ЕДИНЫЙ СБОРЩИК                       │
                    │ читает quota-status-*.json           │
                    │      + spend-*.json                  │
                    │ пишет quota-status-unified.json      │
                    │ ЕДИНСТВЕННЫЙ ПИСАТЕЛЬ                │
                    └──────────────┬──────────────────────┘
                                   │
              ┌────────────────────┼─────────────────────┐
              │                    │                     │
     подвал агента         дверь /go и /od          Presence/UI
     (signal-wire)         (выбор счёта)            (lat-context)
     provider-unified-     accountsFromQuota()
     quota.ts
```

**Лимит сессии идёт ДРУГИМ путём и это правильно:** его видит только тот, кто видит каждый запрос — прокси. Поэтому его источник — журнал дверей (`provider-dump/v1`, `usage_norm`), а не файл квоты: сессий тысячи, они умирают, и класть их в файл показаний аккаунта значило бы смешать предметы и получить файл, который растёт без границы.

## 2. По каждому предмету: факт → владелец → где → кто читает → показ → тишина → проверка

### 2.1 Квота организации

| Шаг | Как есть |
|---|---|
| **Факт** | провайдер отдаёт окна (5ч/неделя/месяц) долей и сроком сброса |
| **Владелец факта** | сборщик провайдера: `open-design-quota.ts` (Control Key, все workspace аккаунта), `opencode-go-quota.ts` (console) |
| **Где лежит** | `~/.claude-local/quota-status-<provider>.json` — **свой файл на провайдера, один писатель** |
| **Кто сводит** | `quota-unified.ts` → `quota-status-unified.json` (единственный писатель) |
| **Кто читает** | `provider-unified-quota.ts` (подвал), `open-design-door.ts` (выбор счёта), внешние потребители (lat-context) |
| **Что показываем** | доля **израсходованного** + сброс; рядом запас `headroomFraction` и «до какого числа держится» `bindsUntil` |
| **Источник молчит** | `null` + `status: unreadable/absent` + `reason` + `ageSec/stale`. **Никогда** не ноль и не фолбэк на другой аккаунт/провайдера |
| **Как проверяем** | `systemctl --user show -p ExecMainStatus --value claude-max-open-design-quota.service`; сравнить `usedCredits/limitCredits` в провайдерном файле с `util` в едином |

### 2.2 Кошелёк (остаток)

| Шаг | Как есть |
|---|---|
| **Факт** | `balanceUsd` в ответе Control API (у OpenDesign — на workspace) |
| **Владелец** | тот же сборщик провайдера |
| **Где лежит** | `accounts[].walletUsd` в едином файле — **строка** (`"1.5000"`), без валюты в поле |
| **Кто читает** | сегодня **никто** (проверено: `walletUsd` не встречается ни в одном читателе signal-wire) |
| **Что показываем** | пока ничего; поле существует, но не выведено |
| **Тишина** | `null` (не 0). Отрицательный баланс — факт, не ошибка (`hello@lifeaitools.com` −$0.08 на 07.11) |
| **Проверка** | `jq '.accounts[] | select(.provider=="open-design") | {account, walletUsd, measuredAt}' quota-status-unified.json` |

**Разрыв:** `walletUsd` — строка без валюты; при появлении второго провайдера с другой валютой поле станет двусмысленным. Предложение к ревью — см. §5.

### 2.3 Расход (деньги, накопление)

| Шаг | Как есть |
|---|---|
| **Факт** | LiteLLM. **Замерено владельцем kiberos-app 07.11:** нестрим — заголовок `x-litellm-response-cost` = окончательная USD-цена без маржи (совпадает с `usage.cost`); **стрим — заголовка НЕТ, и `-original` приходит НУЛЁМ**, цена есть только в ПОСЛЕДНЕМ чанке `usage.cost` и только если клиент попросил `stream_options.include_usage=true` |
| **Владелец** | два писателя по источникам: сборщик kiberos-app (LiteLLM) и `dsh-cost-meter` (ответы dsh) |
| **Где лежит** | `~/.claude-local/spend-<provider>-<экземпляр>.json`, один писатель на файл |
| **Кто сводит** | `quota-unified.ts` → `providers[<id>].spend[]` |
| **Кто читает** | `provider-unified-quota.ts` → `providerSpend[]` (как есть, без свёртки) |
| **Что показываем** | пока ничего — поле есть, UI не читает |
| **Тишина** | пусто/нет поля = «не мерили» (не ноль). Числа нет: любой стрим без `include_usage`, любой не-2xx, таймаут — тогда `null`, а не своя таблица цен |
| **Проверка** | `jq '.providers["opencode-go"].spend' quota-status-unified.json` |

**Кто просит usage в стриме (закрыто замером 07.11, kiberos-app):** `stream_options.include_usage=true` ставит **сам посредник** в исходящем запросе (в дампах `/app/capture/all/` тела уже содержат флаг) — поэтому наши двери видят usage в стриме без всякой просьбы с их стороны. **Граница:** это флаг НАВЕРХ; клиент видит usage в своих чанках только если попросил флаг сам. Харнесс, читающий цену из СВОЕГО ответа, обязан его поставить.

🔴 **Цена в чанке подменяет цену посредника.** LiteLLM берёт `usage.cost` из чанка, если он не `null`, и заменяет им своё вычисленное значение. Поэтому наша дверь с 02.11 (1.2.8, `fca0263`) шлёт `list_cost` вместо нуля — иначе ни один счётчик у посредника не растёт. Если дверь когда-нибудь снова пришлёт ноль, учёт молча обнулится при живом трафике.

🔴 **ОДИН ПРОВАЙДЕР ЦЕНЫ НЕ ДАЁТ ВООБЩЕ (замер 07.11).** OpenDesign в ответе отдаёт usage БЕЗ ЦЕНЫ (только токены и кэш), у модели нет цены в конфиге посредника, наша дверь `/od` ничего не подставляет. Итог живой: **2 221 запрос через `/od` за 6 часов, `sum(spend) = 0`, ни одного платного** — при том что Go на том же пути даёт $0.95 на 84 запроса. То есть для OD «расход в USD» сегодня **не измеряется**, и подставлять цену своей таблицей запрещено. Что есть честно: **кредиты окон** (`usedCredits/limitCredits`) и **кошелёк** (`balanceUsd`, включая отрицательный). Это разные единицы с деньгами, и называть их «расходом в долларах» нельзя.

**След организации (для связи расхода со счётом):** дверь отдаёт `x-kiberos-served-org` и `x-kiberos-org-source`, а LiteLLM префиксует заголовки апстрима — в ответе они приходят как `llm_provider-x-kiberos-served-org` / `llm_provider-x-kiberos-org-source` (голого имени нет), **и в стриме, и в нестриме**. Связывать расход с организацией можно по ним, без второго опроса.
🔴 **Не путать:** `usage.opencode.allowance` — остаток ПОДПИСКИ организации, а не цена; `usage.opencode.list_cost` / `usage.cost` — цена. Это два разных предмета в одном ответе.

**Контракт (влит 3918605):** каждая сумма несёт `currency, total, basis, subject, since, measuredAt, source` (+ `limit?, periodResetAt?`). Строка без предмета/периода/источника **выбрасывается**, а не чинится.

**Как читать накопительные счётчики (поправка владельца dsh 07.11, принимаю целиком):**

1. `total` — **монотонный счётчик**, а не сумма за окно. Внутри одного файла последовательные замеры одного предмета — это ОДИН растущий счётчик, поэтому берётся **последняя** запись по `(файл, subject)`, и **никогда** не складываются последовательные замеры одного файла — это двойной счёт.
2. Складывать можно только **разные файлы**: каждый процесс видит лишь свои ответы, поэтому файлы не пересекаются по факту, а не по обещанию.
3. `since` — **свойство строки**. Для группы он означает лишь «не раньше минимального», и **не** означает «сумма покрывает всё с этого момента»: у позже стартовавшего писателя его `total` ранний отрезок не покрывает.
4. **Из счётчиков нельзя честно получить сумму за произвольное окно `[T0,T1]`** — для периода нужны поштучные события (строки LiteLLM / хранилище событий). Счётчик отвечает только «с тех пор, как начат счёт».
5. **Пропавший или пересозданный файл — «не измерено», а НЕ ноль**, иначе групповой итог тихо уменьшается.

**Канонизация — в сборщике, при ЧТЕНИИ (не хранимый итог).** Три условия, без которых она сама станет источником ошибок (владелец dsh 07.11):
1. итог остаётся **прослеживаемым**: рядом с суммой лежит вклад каждого файла `{file, subject, since, total}` — сломанный писатель виден поимённо;
2. **два файла с одним именем экземпляра — сигнал ошибки, а не строка для сложения** (нарушен «один писатель на файл»);
3. канонизация — **проекция на чтении**, а не новый хранимый агрегат: иначе рядом со счётчиками появится второй счётчик, от которого мы и уходим.

**Период — другой предмет.** Если нужна сумма за окно `[T0,T1]` — это поштучные события, и выдавать их за тот же счётчик нельзя; показывать период можно только под ДРУГИМ именем и с источником-событиями.

### 2.4 Лимит сессии (токены, контекст, кэш)

| Шаг | Как есть |
|---|---|
| **Факт** | `usage` каждого ответа: input/output/reasoning, `cached_tokens`, контекст |
| **Владелец** | прокси: двери `/go` и `/od` пишут `provider-dump/v1` (`usage_norm`) |
| **Где лежит** | `~/.claude-local/provider-dump/<дата>.jsonl` (по строке на вызов) |
| **Кто читает** | сегодня **каждый харнесс сам**: signal-wire считает процент контекста по своему последнему запросу |
| **Что показываем** | «контекст N из M», доля чтения кэша |
| **Тишина** | `null`, не 0 (у Go нет «записано в кэш») |
| **Проверка** | `grep '"session_id":"<id>"' ~/.claude-local/provider-dump/<дата>.jsonl | tail -1 | jq .usage_norm` |

**Разрыв:** это единственный предмет, который **не приведён к одному месту**. Каждый харнесс считает заново и по-своему; кросс-харнессного ответа нет. Предложение — §3.3.

## 3. Предлагаемая форма (на ревью)

### 3.1 Одна поверхность чтения
`quota-status-unified.json` остаётся **единственным** файлом, который читают все. Второй реестр не строим. Схема дополняется аддитивно (`schemaVersion` не поднимаем, пока поля необязательны).

### 3.2 Кошелёк отдельным предметом
Вместо строки `walletUsd` — блок на аккаунте:
```ts
wallet?: { amount: number; currency: 'USD'; measuredAt: string }
```
`walletUsd` сохраняется как переходное поле, пока все читатели не перейдут (срок назвать при ревью). Отрицательное значение разрешено и означает именно минус.

### 3.3 Лимит сессии — эндпоинт прокси, а не файл
Прокси уже видит каждый запрос и уже нормализует usage. Предлагается **одна дверь**:
`GET /admin/session-usage?session=<id>&window=<N>` → `{session, last: {at, model, input, output, cached, contextTokens, contextLimit, cacheShare}, series?: [...]}`
Источник — `provider-dump`, который пишется сейчас. Харнессы читают ответ, а не считают сами. Причина: если каждый харнесс считает сам, мы получаем ровно ту «паутину в связях», от которой предупреждал фаундер.
**Открыто:** нужен ли `series` (история) или достаточно `last` — решает ревью.

### 3.4 Один писатель на файл — закон
Ни один компонент не пишет в чужой файл. Сборщик единого — единственный писатель `quota-status-unified.json`. Деньги — только через `spend-*.json`. Это то же правило, что R8 у пропусков Go: два писателя убивают предмет.

## 4. Молчание источников: матрица поведения

| Что случилось | Что видит читатель | Чего НЕ происходит |
|---|---|---|
| сборщик квоты упал | `stale: true`, `ageSec` растёт, числа остаются с возрастом | не подставляется другой аккаунт |
| у аккаунта нет окон | `status: unreadable`, `reason` | не превращается в 0% |
| провайдер не отдал окно | `usedFraction: null` | не считается «свободно» |
| денег никто не мерил | поля `spend` нет | не печатается $0 |
| денег нет у одного источника | строки других источников остаются | не обнуляется весь расход |
| сессия не найдена | `found: false` | не берётся «похожая» сессия |

## 5. Открытые вопросы — на архитектурное ревью

1. **Lago.** В `kiberos-billing/research/` есть замеры живого Lago v1.55.0 (API-контракт, память/диск), стенд снесён, **в бою не развёрнут**. Нужен ли он в этом потоке вообще — как хранилище событий расхода, — или достаточно файлов + LiteLLM? Решение владельца хранилища (vibe-eventmeter-owner) и фаундера.
2. **Кошелёк:** вводим блок `wallet` или оставляем `walletUsd` строкой? Если вводим — назвать срок снятия старого поля.
3. **Расход:** кто канонизирует «последняя запись на `(файл, subject)`» и складывает файлы — сборщик или читатель? Сейчас сборщик просто конкатенирует, читатель отдаёт как есть. Предлагаю канонизировать в сборщике: правило одно и не размножается по потребителям.
3a. **Сумма за окно** (день/неделя/месяц) из счётчиков не выводится — нужны поштучные события. Значит: либо период не показываем, либо он приходит из LiteLLM-событий (и тогда это другой предмет — «расход за период», с явным источником). Решение — на ревью.
4. **Лимит сессии:** эндпоинт `/admin/session-usage` — верное место? Нужна ли история (`series`) или только последний замер?
5. **Модели и деньги — ЗАКРЫТО ЗАМЕРОМ (kiberos-app):** нестрим — заголовок окончательный; стрим — цена только в последнем чанке; флаг `include_usage` ставит САМ посредник наверх, клиент — только для своего ответа. **Новый вопрос вместо закрытого:** что делаем с провайдером, который цены не отдаёт вообще (OpenDesign)? Принимаем «кредиты + кошелёк» как его единицу и не называем это долларами — или требуем цену от поставщика. Решение — на ревью.
6. **Чтение `/spend/logs` — ОТВЕТ ПОЛУЧЕН:** только мастер-ключ (read-only админ получает 401), отдельный ключ чтения не выдаётся. Живём на числе из ответа; агрегат за окно — разово по запросу владельца LiteLLM (`sum(spend) group by org/model`), постоянной двери в базу нет.
7. **Ретенция:** `spend-*.json` — накопительные; `provider-dump` — по дням с TTL. Кто и когда чистит деньги, чтобы `since` не врал?

## 6. Чего не делаем (запреты заказчика)

- не строим второй реестр рядом с существующим;
- не считаем деньги своей таблицей цен;
- не заставляем каждый харнесс звать провайдера;
- не ставим `max_budget` на агентские ключи — второй счётчик квоты разойдётся;
- не смешиваем квоту, кошелёк и лимит сессии в одно число.

## 7. Что уже работает и не требует кода

- единый читатель квоты и файл `quota-status-unified.json` (инвариант «пусто = не измерено»);
